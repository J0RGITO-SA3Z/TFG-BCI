\section{Normalización de los \textit{trials}}
\label{sec:normalizacion}

En la mayoría de aplicaciones de algoritmos de aprendizaje automático es necesaria la normalización de los datos que va a recibir el modelo. Este proceso se realiza con el fin de que las distintas variables presenten escalas comparables, evitando que aquellas con magnitudes mayores dominen el proceso de aprendizaje y facilitando así la identificación de relaciones relevantes entre los datos.

La normalización adquiere una relevancia especial en el contexto de los sistemas BCI (Brain-Computer Interface), donde uno de los principales desafíos es la variabilidad intersujeto. Las diferencias anatómicas y fisiológicas entre individuos, como el grosor del cráneo, las características del cuero cabelludo, el tipo de cabello o la propia actividad cerebral, dificultan la capacidad de generalización de los modelos entre distintos sujetos. Además, incluso entre diferentes sesiones de un mismo individuo pueden aparecer variaciones debidas a cambios en la posición de los electrodos, el estado mental del sujeto u otros factores relacionados con el proceso de adquisición de señales.

Mediante el proceso de normalización en sistemas BCI se busca favorecer la generalización intersujeto, permitiendo utilizar datos procedentes de múltiples individuos y aumentando significativamente la cantidad de datos disponibles para entrenamiento. Además, este proceso reduce la necesidad de reentrenar el modelo cada vez que el usuario retira y vuelve a colocarse el electroencefalógrafo.

\subsection{\textit{Baseline}}
\label{subsec:baseline}

Uno de los métodos más básicos de normalización intersujeto en sistemas BCI es la técnica de baseline. Esta técnica se basa en la hipótesis de que cada individuo presenta una actividad cerebral basal en estado de reposo y que, al realizar una determinada tarea o estímulo, las nuevas fuentes de actividad cerebral se superponen a dicha señal base.

Por ello, antes de comenzar una grabación o una sesión de uso del sistema BCI, se realiza una fase de calibración en reposo, cuya duración puede variar desde varios segundos hasta varios minutos. Durante este periodo se registran señales EEG del sujeto y se calcula una señal media de referencia. Posteriormente, esta señal basal se resta del resto de la grabación con el objetivo de reducir la variabilidad entre sujetos y hacer que las señales obtenidas presenten características más homogéneas entre distintos individuos.

En un principio se iba a utilizar este método por ser uno de lo más utilizados pero tras la elección del modelo MiRepNet y debido a que los pesos de dicho modelo vienen preentrenados utilizando la normalizacion de alineamiento euclideo acabamos desechando este método.

\subsection{Alineamiento Euclídeo}
\label{subsec:alineamiento_euclideon}

El alineamiento euclideo, a diferencia de otros métodos de normalización por escalado como Min-Max, no pretende mantener los valores en un intervalo definido (por ejemplo, entre 0 y 1). 
Trata de alinear la distribución de los datos de diferentes sujetos para que le sea más fácil generalizar. Este alineamiento lo consigue haciendo que la matriz de covarianza media entre canales de cada usuario sea igual a la matriz identidad.

Para aplicar el alinemiento euclideo, dado un sujeto con $n$ trials $\{X_i \in \mathbb{R}^{C \times T}\}_{i=1}^{n}$, donde $C$ es el número de canales y $T$ el número de muestras temporales, en primer lugar se calcula tanto la matriz de covarianza de referencia como la media de las covarianzas de todos los trials:

\begin{equation}
    \bar{R} = \frac{1}{n} \sum_{i=1}^{n} X_i(X_i)^\top.
\end{equation}

A continuación, cada trial se normaliza multiplicándolo por la raíz cuadrada inversa de dicha matriz de referencia:

\begin{equation}
    \tilde{X}_i = \bar{R}^{-1/2} X_i, \quad i = 1, \ldots, n.
\end{equation}

Tras aplicar esta transformación la covarianza media de los trials transformados es la matriz identidad:

\begin{equation}
    \frac{1}{n} \sum_{i=1}^{n} \tilde{X}_i \tilde{X}_i^\top = I.
\end{equation}

En el gráfico \ref{fig:proyeccion_alineamiento_euclideo} se proyecta en un espacio de 2 dimensiones, mediante t-SNE, los datos de EEG de diferentes sujetos antes y después del alineamiento euclídeo. En él se observa como, efectivamente, el alineamiento Euclídeo alinea los datos de los diferentes sujetos.

A la hora de la implementación, denominaremos \textit{matriz de transformación} a la raíz cuadrada inversa de la matriz de covarianza de referencia. Para poder usar este método, hay que calcular una matriz de transformación para cada sujeto por separado. Además, es importante calcular una matriz con los datos de entrenamiento y otra con los datos de \textit{test} para evitar fugas de información.

En cuanto a la implementación en tiempo real, se valoraron dos alternativas sobre cómo calcular la matriz de transformación para los datos de \textit{test}:

\begin{itemize}
    \item \textbf{Alineamiento euclídeo dinámico:} trata de mantener $X$ ventanas consecutivas en un buffer circular y recalcular la matriz de transformación para cada predicción. Es la opción más precisa pero también la más compleja, tanto en implementación como en coste computacional. Lo cual en un sistema de tiempo real puede derivar en delays demasiado largos.

    \item \textbf{Matriz calculada en training:} consiste en calcular la matriz de transformación únicamente con los datos de \textit{fine-tuning} del sujeto y reutilizarla para los datos de test. Desde el punto de vista de implementación, es mucho más sencillo, y computacionalmente, el alineamiento euclídeo se reduce a una multiplicación de matrices fácilmente paralelizable con NumPy. También existe la posibilidad de acelerarlo por GPU, pero dado el bajo \textit{delay} que introduce la operación con NumPy y la complejidad adicional de medir la mejora teniendo en cuenta el tiempo de transporte de datos, se decidió mantener los cálculos en CPU.
\end{itemize}

Para determinar si la segunda alternativa era viable, se realizó un experimento de validación cruzada de 5 \textit{folds} sobre los 8 sujetos disponibles, comparando ambas estrategias. En la condición de \textit{EA independiente} se calcula una matriz de transformación distinta para el conjunto de finetuning y para el conjunto de test. En la condición de \textit{EA compartida} la matriz se calcula únicamente con los datos de finetuning y se reutiliza para alinear el conjunto de test. 

Cabe resaltar que, en este caso no existe fuga de datos porque no se usan los datos de test en entrenamiento. Esto solo ocurriría si la matriz compartida se calculase tanto con los datos de test como con los de finetuning.
